1. INTRODUCTION                                *tern* *tern.nvim* *tern-intro*

Tern (https://github.com/OzkrAC/tern) writes documents as HTML files. A
note's first line loads `tern.js`, and everything after that line is the
note, written in Tern's markdown-like syntax. Opened in a browser, tern.js
renders the note in place.

tern.nvim is the Neovim side of Tern. It:
• gives the filetype `tern` to every .html file that loads tern.js
  (|tern-detection|);
• runs `tern lsp`, Tern's language server, for each note. The server gives
  diagnostics, completion, go to definition, references, rename, hover,
  symbols, folding and quick fixes, in the note and across notes
  (|tern-lsp|);
• draws virtual text from the server's outline: block labels, what each
  reference reads as, equation numbers, and simple TeX as Unicode
  (|tern-render|);
• serves a live preview that refreshes the browser as you type
  (|tern-preview|);
• writes a note's first line, and runs `tern check` and `tern build`
  (|tern-commands|);
• highlights the syntax (|tern-highlight|).

The plugin is a client of `tern lsp`, with no grammar of its own. Positions,
structure, diagnostics and folds come from the server, which runs the engine
the browser runs, so the editor and the page cannot disagree. Highlighting is
the one exception: syntax/tern.vim is lexical, so it is fast and works
without Node.

Detection                                                     *tern-detection*

A file is a note when its name ends in .html or .htm and one of its first
1000 lines holds a plain <script> that loads a file named tern.js. The rule
for that line:
• the tag has no `async`, `defer` or `data-built` attribute and no
  `type=module`, because tern.js must run while the page is parsed;
• its src is tern.js, optionally after a path and before a ?query or #hash,
  quoted or not;
• a tag inside a complete <!-- … --> comment does not count, and after an
  unclosed comment nothing on the line counts.
This is the engine's rule (`DETECT` in Tern's cli/note.js), written in Lua in
lua/tern/detect.lua, so detection needs no Node. Other HTML files keep the
filetype `html`.

The canonical first line, which |:TernInit| and `tern new` write, is: >html
    <!doctype html><meta charset="utf-8"><script src="tern.js"></script>
<
In a note, the ftplugin sets 'commentstring' to `<!-- %s -->`. It also
removes `t` from 'formatoptions', because hard wrapping breaks constructs
that must stay on one line: openers, leaves and table rows.

2. REQUIREMENTS                                            *tern-requirements*

• Neovim 0.11 or later. On an older Neovim the plugin warns and defines no
  commands.
• Node 22 or later, as `node` on PATH.
• The Tern CLI: tern-cli.js, from a checkout of
  https://github.com/OzkrAC/tern. See |tern-cli|.

The language server, the virtual text, |:TernCheck| and |:TernBuild| need
Node and the CLI. Everything else works without them: |tern-without-node|.
The plugin needs no other Lua plugin.

3. INSTALLATION                                            *tern-installation*

lazy.nvim: >lua
    {
      'OzkrAC/tern.nvim',
      opts = {}, -- passed to require('tern').setup()
    }
<
packer.nvim: >lua
    use({
      'OzkrAC/tern.nvim',
      config = function()
        require('tern').setup({})
      end,
    })
<
Native packages (|packages|): >sh
    git clone https://github.com/OzkrAC/tern.nvim \
      ~/.local/share/nvim/site/pack/tern/start/tern.nvim
<
Then run `:helptags ALL` to index this help file.

You do not need to lazy-load the plugin. plugin/tern.lua only defines the
commands, and the modules load when the first note opens or a command runs.
|tern.setup()| is optional: without it the defaults apply.

The Tern CLI                                                        *tern-cli*

Get Tern and make its CLI findable: >sh
    git clone https://github.com/OzkrAC/tern
    cd tern && npm link     # puts `tern` on PATH
<
Instead of `npm link`, you can set $TERN_CLI to /path/to/tern/tern-cli.js,
or set |tern-option-cmd|.

How the plugin finds the CLI                                 *tern-cli-lookup*

For each note, the plugin uses the first of these sources that applies:
1. `cmd` in |tern.setup()| (|tern-option-cmd|), used as given.
2. $TERN_CLI, the path of tern-cli.js. When it is set but is not a file, the
   search stops there with an error.
3. tern-cli.js in the note's directory or any directory above it, as when
   the note is inside a Tern checkout.
4. tern-cli.js next to the tern.js the note loads, with symbolic links
   followed. So a note whose tern.js is a link to a checkout's tern.js finds
   that checkout. A root-relative src (/tern.js) is tried under every
   directory above the note; a URL src (https://…, //…) is skipped.
5. `tern` on PATH, when it is tern-cli.js itself (`npm link`, `ln -s`) or a
   script that runs it. Any other `tern` is skipped, because an unrelated
   npm package has that name.

Sources 2 to 5 run tern-cli.js with the `node` on PATH, which must be Node 22
or later. Each node binary is checked once a session. For a buffer without a
file, the search starts in the current directory.

The language server is the CLI with `lsp`. |:TernCheck| and |:TernBuild| run
the same CLI with `check` and `build`. `:checkhealth tern` shows which source
found the CLI for the current buffer (|tern-health|).

4. SETUP                                           *tern-setup* *tern.setup()*

require('tern').setup({opts})

{opts} is merged over the defaults below. Each call starts again from the
defaults: options from an earlier call are not kept. The modules read the
options when they use them, so a change applies to the next note that opens,
the next draw, or the next command.

The defaults: >lua
    require('tern').setup({
      cmd = nil,
      lsp = true,
      watch = false,
      fold = true,
      render = {
        enabled = true,
        labels = true,
        refs = true,
        math = true,
        conceal = true,
      },
      preview = {
        host = '127.0.0.1',
        port = 0,
        open = true,
        browser = nil,
        update = 'change',
      },
    })
<
cmd                                                          *tern-option-cmd*
    List or function. Default: nil.
    The language server command, such as: >lua
        cmd = { 'node', '/path/to/tern/tern-cli.js', 'lsp' }
<
    With nil, the plugin finds the command for each note (|tern-cli-lookup|).
    A list's first item must be an executable; when it is `node`, its version
    is checked. The items before `lsp` are the CLI that |:TernCheck| and
    |:TernBuild| run. Without an `lsp` item, those commands find the CLI
    from the other sources. A function is passed to |vim.lsp.start()| as is
    (see `cmd` in |vim.lsp.ClientConfig|).

lsp                                                          *tern-option-lsp*
    Boolean. Default: true.
    Starts `tern lsp` for each note. With false, no server starts, and notes
    fold by headings (|tern-lexical-folds|) and get no virtual text.
    |:TernCheck| and |:TernBuild| still work.

watch                                                      *tern-option-watch*
    Boolean. Default: false.
    Lets the server watch the files under its root, through Neovim's file
    watcher, for changes made outside Neovim: an add-on edited in another
    program takes effect in the notes that load it at once, and a file
    renamed by git is seen by the link checks. Off, such changes are seen at
    the note's next change, save, open or close. Neovim's watcher on Linux
    polls the tree, so a very large root (one holding node_modules) costs
    with it on.

fold                                                        *tern-option-fold*
    Boolean. Default: true.
    Sets the folds of each window that shows a note: from the server, or by
    headings without one, and a fold for the head (|tern-folding|). With
    false, the plugin does not touch the fold options, and the head stays
    in sight (|tern-render-head|).

render                                                    *tern-option-render*
    Table. The virtual text drawn from the server's outline (|tern-render|).

render.enabled                                    *tern-option-render.enabled*
    Boolean. Default: true.
    Draws the virtual text in each note as it opens. With false, nothing is
    drawn until `:TernRender on` (|:TernRender|).

render.labels                                      *tern-option-render.labels*
    Boolean. Default: true.
    A numbered block's label, such as "Theorem 1", at the end of its opener
    line.

render.refs                                          *tern-option-render.refs*
    Boolean. Default: true.
    What each @reference reads as on the page, right after it.

render.math                                          *tern-option-render.math*
    Boolean. Default: true.
    Simple TeX as Unicode beside each formula, and the equation numbers of
    display math.

render.conceal                                    *tern-option-render.conceal*
    Boolean. Default: true.
    Draws math with a Unicode form in place of its source, a block's
    opener in place of its syntax, with its other attributes and its
    closer hidden, and an inline element as its content (|tern-render|);
    keeps the head folded
    (|tern-render-head|). The source shows again while the cursor is on
    it. The ftplugin sets 'conceallevel' to 2 in the note's window. With
    false, nothing is hidden: the Unicode form follows the source, labels
    go at the end of the opener line, the head's fold stays open, and
    'conceallevel' is left alone.

preview                                                  *tern-option-preview*
    Table. The |:TernPreview| server (|tern-preview|).

preview.host                                        *tern-option-preview.host*
    String. Default: '127.0.0.1'.
    The address the server listens on: an IP address, or a name that
    resolves to one. The preview URL uses it.

preview.port                                        *tern-option-preview.port*
    Number. Default: 0.
    The port. With 0, the server takes any free port.

preview.open                                        *tern-option-preview.open*
    Boolean. Default: true.
    Opens the page in a browser on |:TernPreview|. With false, the URL is
    only printed.

preview.browser                                  *tern-option-preview.browser*
    String or list. Default: nil.
    The command that opens the page, with the URL added as its last
    argument: 'firefox', or { 'firefox', '--new-window' }. It runs detached.
    With nil, the page opens with |vim.ui.open()|.

preview.update                                    *tern-option-preview.update*
    String. Default: 'change'.
    When the page of a note refreshes. With 'change', it follows the note's
    buffer as you type, written or not: a modified note is served from its
    buffer (|tern-preview-unsaved|). With 'write', it refreshes when you
    write, and the server serves the files on disk only.

5. COMMANDS                                                    *tern-commands*

:TernInit [{src}]                                                  *:TernInit*
    Makes the current buffer a note. It inserts the canonical first line at
    the top: >html
        <!doctype html><meta charset="utf-8"><script src="SRC"></script>
<
    It also sets the filetype to `tern`. One |undo| removes the line. In an
    empty buffer the cursor goes to line 2, where the note starts.

    SRC is chosen like this:
    • With {src}, a file is written relative to the note. A directory that
      holds tern.js stands for that tern.js. Anything else, such as a URL,
      is written as given. %, #, ~ and $VAR at its start are expanded.
    • Without {src}, it is the nearest tern.js in the note's directory or
      above, relative to the note. Without one, it is `tern.js`, and the
      message warns that none was found.
    The src must name a file called tern.js, or the line would not make a
    note; otherwise nothing is written.

    :TernInit refuses a buffer that has no file (write it first), a buffer
    that is already a note, and a buffer that is not 'modifiable'. It warns
    when the note's directory does not exist yet, and when the file name
    does not end in .html, because a browser would not render it.

:TernCheck [{path} ...]                                           *:TernCheck*
    Runs `tern check --json` on each {path}, a file or a folder, or on the
    current buffer's file. The diagnostics go to the |quickfix| list, which
    opens when there are any. Each item has the file, the line and column
    range, the type (E, W or I) and "CODE: message". The diagnostic's hint
    is in the item's `user_data.hint`. %, #, ~ and $VAR at the start of a
    {path} are expanded.

    The check runs in the background and reads the files on disk. When the
    buffer has unsaved changes, the message says so. The language server
    checks the buffer itself as you type (|tern-diagnostics|); :TernCheck is
    for files and folders that are not open.

    The quickfix list's title is "tern check" and the paths. When the
    current list is a tern check list, a new run replaces it, even a clean
    one. Otherwise a run that finds problems adds a new list. A clean run
    says "tern check: no problems". A usage error, such as a path that does
    not exist, shows tern check's message.

:TernSearch {word} ... [{path} ...]                              *:TernSearch*
    Runs `tern search --json` for the words, over each {path}, a file or a
    folder, or over the working directory when none is given: an argument
    that names an existing file or folder is a path, the others are the
    query. The hits go to the |quickfix| list, which opens when there are
    any: one item per heading's section or named block with an id, at its
    line, with "LABEL TITLE: passage" as its text and the block's id, kind,
    page title and score in `user_data`. A word stands for the words it
    begins, so `pythag` finds Pythagoras. The notes are read from disk.

    An argument that starts with `--` goes to `tern search` as it is:
    `:TernSearch --index=search.json pythag` searches the index that
    `tern index` wrote instead of reading the notes, the same hits from
    one file; the value of `--index=` is expanded as a path (%, ~, $VAR).

    The list's title is "tern search" and the words. When the current list
    is a tern search list, a new search replaces it, even one that finds
    nothing; otherwise a search that finds something adds a new list, and
    one that finds nothing only says so.

:TernBuild [{out}]                                                *:TernBuild*
    Runs `tern build FILE -o OUT` on the current buffer's file, in the
    background. FILE is built into a static page: the HTML the browser
    would mount, already in the file.

    {out} defaults to NAME.built.html beside the note, so its relative URLs
    (tern.js, add-ons, images) still resolve. An {out} that ends in / is a
    folder: the page goes into it under the note's file name. %, #, ~ and
    $VAR at the start of {out} are expanded.

    The build reads the file on disk; with unsaved changes the message says
    so. The message names the file written, says how many diagnostics the
    note has (|:TernCheck| lists them), and repeats tern build's warnings.

:TernMove [{from}] {to}                                            *:TernMove*
    Moves the current buffer's file, or {from}, to {to}, and fixes the
    links: those to it from other notes, and its own, which now start from
    its new folder. These are the edits `tern mv` makes. The language server
    works them out (workspace/willRenameFiles), so unsaved changes in open
    notes count. {from} may be any file, or a folder. A {to} that is a
    folder, or ends in /, receives {from} under its own name. Missing
    folders on the way are created. %, #, ~ and $VAR at the start of a path
    are expanded. >vim
        :TernMove notes/linear/
        :TernMove notes/img notes/pictures
<
    The server reads the notes under its root (|tern-lsp|) and the open
    buffers. The buffer of a moved file is renamed and written at its new
    path, unsaved changes included, as |vim.lsp.util.rename()| does. Other
    open buffers get their edits and are written; one with unsaved changes
    gets them but is not written, and the message names it. A file that no
    buffer shows is edited without opening it as a note: no autocommands
    run, and its bytes stay as they were but for the edits. The message
    counts the links fixed.

    Nothing moves when {to} exists, when a folder would move into itself,
    or when no server runs for the file. A note with a <base href> keeps its
    links, and the server's message names it. Files that are not notes are
    not edited; `tern mv --dry-run` lists those that name a moved file.

:TernPreview                                                    *:TernPreview*
    Serves the current buffer's file over HTTP, prints its URL and, with
    |tern-option-preview.open|, opens it in a browser. The page refreshes
    as you change the note, and each time you write it
    (|tern-option-preview.update|). The file must exist on disk. See
    |tern-preview|.

:TernPreviewStop                                            *:TernPreviewStop*
    Stops the preview server and closes every connection. The server also
    stops when Neovim exits.

:TernRender [{state}]                                            *:TernRender*
    Shows or hides the virtual text (|tern-render|) in the current buffer.
    {state} is `on`, `off` or `toggle`; without it, the command toggles.
    `on` also works when |tern-option-render.enabled| is false.

6. THE LANGUAGE SERVER                                              *tern-lsp*

For each note, the plugin starts `tern lsp` with |vim.lsp.start()|, or
attaches the note to a server that is already running. The client is named
`tern`. One server runs per root: the nearest directory above the note that
holds tern-cli.js or tern.js, else the note's own directory. Notes below the
same tern.js share a server.

The server analyses a note when it opens, and 150 ms after you stop typing.
It runs the analysis that `tern check` runs, with the engine the browser
runs. The features below use Neovim's own mappings and functions
(|lsp-defaults|); the plugin adds no mappings.

Diagnostics                                                 *tern-diagnostics*
    Errors, warnings and infos as you type, with the source `tern` and a
    code such as `ref.dangling`. The message ends with the hint, on a line
    of its own, when there is one.
    • |]d-default| and |[d-default| go to the next and the previous
      diagnostic; |]D-default| and |[D-default| go to the last and the first.
    • |CTRL-W_d-default| shows the diagnostics at the cursor in a float.
    • |vim.diagnostic.setqflist()| and |vim.diagnostic.setloclist()| list
      them.
    Neovim shows diagnostics as signs and underlines. To see the messages at
    the end of the line, use `vim.diagnostic.config({ virtual_text = true })`
    (|vim.diagnostic.config()|).

Completion                                                   *tern-completion*
    Completion offers what may come next where you type:
    • after `:::`, container names, and a closer for each open container;
    • after `:::/`, only the closers of the containers open at that line;
    • after `::`, leaf names;
    • after `:`, inline element names;
    • after `@`, and after `](#` in a link, the note's ids, each with what a
      reference to it reads as.
    The names come from the note's vocabulary (its head scripts and
    add-ons), then the core blocks `meta` and `macros`, then the HTML
    elements allowed at that place. Nothing is offered inside code, math,
    raw HTML or a raw container.

    Right after a keystroke, before the server has analysed the change,
    completion reads what you typed from the buffer and answers with the
    names and ids of the last analysis.

    Use |i_CTRL-X_CTRL-O|: 'omnifunc' is |vim.lsp.omnifunc()|. To complete as
    you type, after the trigger characters `:` and `@`, enable
    |lsp-completion| for the client: >lua
        vim.api.nvim_create_autocmd('LspAttach', {
          callback = function(ev)
            local client = vim.lsp.get_client_by_id(ev.data.client_id)
            if client and client.name == 'tern' then
              vim.lsp.completion.enable(true, client.id, ev.buf,
                { autotrigger = true })
            end
          end,
        })
<
Go to definition                                             *tern-definition*
    From a reference `@id`, a fragment link `[text](#id)` or a footnote
    reference `[^x]`, it goes to the declaration: the `#id` of an attribute
    group, the footnote's `[^x]:`, or the heading whose slug is the id.
    From a named closer `:::/name`, it goes to the opener's name. From a
    link to another file, `maps.html#rn`, it goes to the id there, or to
    the file's first line without a fragment (|tern-across-files|).
    Use |CTRL-]| ('tagfunc' is |vim.lsp.tagfunc()|) or
    |vim.lsp.buf.definition()|.

References                                                   *tern-references*
    From a declaration or from any reference, it lists every `@id`, fragment
    link and footnote reference to the id, and every link `page.html#id` to
    it from the other notes. Nothing inside code or math is a reference.
    Use |grr| (|vim.lsp.buf.references()|).

Rename                                                           *tern-rename*
    Renames an id together with all its references, in its note and in the
    links `page.html#id` to it from the other notes, or an element's name
    together with its named closer, in one edit. Renaming a heading's slug
    adds `{#new}` to the heading line. The server refuses an id that `@`
    could not reach, an id the note already uses, and the ids that come from
    footnote labels, and it says why. Use |grn| (|vim.lsp.buf.rename()|).
    The other notes are edited in their buffers, loaded if need be, and not
    written: |:wall| writes them. To rename or move a file, with its links,
    use |:TernMove|.

Across files                                               *tern-across-files*
    A link to another file with a fragment, `maps.html#rn`, is a reference
    to that id. Definition, references and rename follow it: the other
    notes under the server's root, and every open note, are read as link
    checking reads them, an open note as it is in its buffer. A link to a
    file that is not a note goes to the element with that id, or the
    heading with that anchor in a Markdown file; rename is refused there.

Code actions                                               *tern-code-actions*
    |gra| (|vim.lsp.buf.code_action()|) on a diagnostic offers its quick
    fixes, when it has one: a near id for a reference to no id, or its
    escape `\@name`; the definition of a footnote without one; the closer
    of an unclosed block or display math; a near name for an unknown name;
    braces around an opener's attributes written without them; the disk's
    spelling for a link in another case.

Workspace symbols                                     *tern-workspace-symbols*
    |vim.lsp.buf.workspace_symbol()| searches the headings, and the blocks
    with an id or a title, of every note under the root and every open
    note, by name or id (`#rn`), into the quickfix list. The notes are
    parsed, their code not run.

Hover                                                             *tern-hover*
    |K| (|vim.lsp.buf.hover()|) on an id, a reference or a declaration shows
    what a reference to it reads as, such as "Theorem 1 — Rank–nullity",
    with its kind, its id and the line where it is declared. On an
    element's name, it shows the HTML element the name becomes, and why: a
    schema entry, an HTML element, or no entry (a <div>).

Symbols                                                         *tern-symbols*
    |gO| (|vim.lsp.buf.document_symbol()|) lists the headings, containers and
    leaves, nested, in the location list.

Folding                                                         *tern-folding*
    With |tern-option-fold|, each window that shows a note gets these
    window-local options:
        'foldmethod'    expr
        'foldexpr'      v:lua.require'tern.lsp'.serverfold(v:lnum)
        'foldlevel'     99, so every fold starts open
        'foldtext'      v:lua.require'tern.head'.foldtext()
        'foldminlines'  0, so that a one-line head can be closed
        'fillchars'     with `fold: `, spaces after a closed fold's text
                        instead of dots, unless 'fillchars' sets `fold:`
    A window that already folds this way keeps its 'foldlevel'. The server
    folds containers, fences, display math, tables, lists, footnote
    definitions, raw HTML blocks, and the section of each heading. Use |zc|,
    |zo|, |za|, |zM| and |zR|.
    The head, the lines up to the tern.js line, is a fold of its own, at
    level 2 inside a level-1 fold of the same lines. |tern-render-head|
    keeps the inner one closed. The outer one stays open, because a fold
    that appears takes the state of the fold before it, and the folds
    after the head must not start closed. On the head's fold, 'foldtext'
    shows what the head holds; on the others, Neovim's |foldtext()|.

                                                          *tern-lexical-folds*
    Without a server (|tern-option-lsp| is false, or the server cannot
    start), notes fold by headings: a heading of level N starts a fold of
    level N, and headings inside fenced code are ignored. The head is
    folded as above. 'foldexpr' is then
    `v:lua.require'tern.lsp'.foldexpr(v:lnum)`.

When the server does not run                               *tern-lsp-fallback*
    When no server can start (no node, no CLI, or a command that exits at
    once), a notice says why, once a session. The note opens without
    errors and folds by headings. A server that crashes is restarted once.
    When it crashes again within a minute of that restart, it stays down,
    a notice says so, and its notes fold by headings. |:edit| a note to try
    again.

The outline                                       *tern-outline* *TernOutline*

After each analysis, the server sends a `tern/outline` notification, a
digest of the note's structure. The plugin keeps the last one for each
buffer, then fires the |User| event `TernOutline` with
`data = { buf = buf }`. |tern.lsp.outline()| returns it. The virtual text
is drawn from it, and you can use it too: >lua
    vim.api.nvim_create_autocmd('User', {
      pattern = 'TernOutline',
      callback = function(ev)
        local o = require('tern.lsp').outline(ev.data.buf)
        print(#o.headings .. ' headings, ' .. #o.refs .. ' references')
      end,
    })
<
Every `line` and `endLine` is a 1-based file line. Every `col` and `end` is
a 1-based UTF-16 column, and `end` is exclusive. To get the 0-based byte
index of a column in a line, use
`vim.str_byteindex(line, 'utf-16', col - 1, false)`. A field with no value
is left out. The fields:

    uri, version  the document, and the version that was analysed
    headings      { line, depth, id, text }
    blocks        { line, endLine, kind ('container' or 'leaf'), name, id,
                  title, label, colons }
    refs          { line, col, end, id, text, resolved }
    math          { line, col, endLine, end, display, number, tex }
    tables        { line, endLine }
    raw           { line, endLine, kind }
    inline        { line, col, end, name }

Tern's documentation describes each field: docs/tools.html#outline in the
Tern repository. While you type, the outline lags behind the buffer until
the next analysis. A buffer's outline is forgotten when the buffer is
unloaded.

7. VIRTUAL TEXT                                                  *tern-render*

The plugin draws text from the outline (|tern-outline|) beside the source,
so that the source shows what the page will show. With
|tern-option-render.conceal|, math and the syntax of blocks and inline
elements are drawn in place of their source, which shows again while the
cursor is on it. Each
kind has its own flag:

Labels (|tern-option-render.labels|)
    At the end of a numbered block's opener line, the label that the
    vocabulary gives the block, with its number: `Theorem 1`. When the
    block's title is not visible on that line, ` — Title` follows,
    shortened to 60 characters. With |tern-option-render.conceal|, the
    label goes in place of the opener instead (see Blocks below), and at
    the end of the line while the cursor is on it. Highlight:
    |hl-TernVirtLabel|.

References (|tern-option-render.refs|)
    Right after each `@id` that resolves, what it reads as on the page:
    `Theorem 1`, a heading's text, `(1)`, shortened to 40 characters. A
    reference that does not resolve gets none: its diagnostic says why.
    Highlight: |hl-TernVirtRef|.

Math (|tern-option-render.math|)
    For inline math `$…$`, the Unicode form in place of the source, so
    that `$\mathbb{R}^n$` reads `ℝⁿ`. On the cursor line the source shows,
    and the Unicode form follows the closing `$`.
    For display math, the Unicode form in place of its TeX, line by line,
    with the `$$` hidden, and the equation number, such as `(1)`, at the
    end of the closing line:
        $$
        \begin{align}
        f(x) &= (x + 1)^2 \\        f(x) = (x + 1)²
             &= x^2 + 2x + 1 \\          = x² + 2x + 1
             &\ge 1                      ≥ 1
        \end{align}
        $$ {#eq-a}                  {#eq-a}  (1)
    The lines of `$$`, `\begin` and `\end` stay as blank lines, as Neovim
    hides text but not lines. The one-line form `$$ x^2 $$ {#eq}` reads
    `x² {#eq}  (1)`. While the cursor is on any line of the equation, its
    source shows; the Unicode form of TeX on one line goes before the
    number at the end of the closing line.
    Display math is drawn in place when its TeX is one line, or an
    environment written one row a line, such as align, cases or a matrix
    (|tern-tex|), between a `$$` line
    and a closing `$$` line. Any other display math keeps its source and
    its `$$`, and TeX on one line gets its Unicode form at the end of the
    closing line.
    The source stays hidden under the cursor too when 'concealcursor' has
    the mode, and shows everywhere with 'conceallevel' 0 or
    |tern-option-render.conceal| false. Inline math on two lines is never
    hidden. Highlights: |hl-TernVirtMath| for the formula,
    |hl-TernVirtLabel| for the number.

Blocks (|tern-option-render.conceal|)
    A block's opener in place of its syntax: the label (or, without one,
    the block's name), the title as written, and the id of its
    attributes. Its other attributes and its closer are hidden, and an
    attribute line above it shows only its id:
        {#a1 .wide}                          {#a1}
        :::theorem[Main idea]{#t1 .big}      Theorem 1 Main idea {#t1}
        Body.                                Body.
        :::
        :::row{cols=2}                       row
    Leaves read the same way, `Figure 1 A cap {#f1}`, and a leaf without a
    label shows its name in angle brackets, a placeholder for what the
    page puts there: `⟨toc⟩`.
    A container with a verbatim body (`:::meta`, `:::macros`, `{raw}`)
    is tinted from its opener to its closer, like a code block, and its
    body stays as written:
        :::meta                  meta               ┐
        title: Linear maps       title: Linear maps │ tinted
        :::                                         ┘
    `+++` cells and attribute lines before anything but a block keep their
    source, as the outline does not hold them. On the cursor line the
    source shows, with the label at its end. Highlights: |hl-TernVirtLabel|
    for the label, |hl-TernVirtName| for the name, |hl-TernVirtVerbatim|
    for a verbatim block's name, |hl-TernVerbatim| for its tint,
    |hl-TernVirtId| for the id.

Inline elements (|tern-option-render.conceal|)
    An inline element as its content: `:name[` and `]` hidden, and its
    attributes as their id. The content is highlighted, kbd, code and samp
    as code. sub and sup read as Unicode scripts when every character has
    one, q between quotes, and an element without content as its name in
    angle brackets:
        Press :kbd[Ctrl]+:kbd[S].          Press Ctrl+S.
        x :sup[-1] and :q[so]{#q1}         x ⁻¹ and “so”{#q1}
        Super :wbr[]califragilistic        Super ⟨wbr⟩califragilistic
    An element over several lines keeps its source. A label that the
    vocabulary gives an inline element is not drawn: the outline does not
    hold it. On the cursor line the source shows. Highlights:
    |hl-TernInline| and |hl-TernInlineCode| for the content,
    |hl-TernVirtName| for the name, |hl-TernVirtId| for the id.

The head (|tern-option-render.conceal|)                     *tern-render-head*
    The head, from the doctype to the tern.js line, with any window.TERN
    script, <title> or <style>, is folded into one line that says what it
    holds: its title, `schema` for window.TERN, other scripts, `style`,
    and the add-ons of the tern.js line's `data-use`:
        <!doctype html><meta charset="utf-8">
        <script>                              ⟨head⟩ schema · style
          window.TERN = { schema: … };
        </script>
        <style>…</style>
        <script src="tern.js"></script>
    It is folded when the note is first drawn in a window, opens when the
    cursor moves into it (from the line below, onto its last line) or
    Insert mode starts there, and folds again when the cursor leaves. This
    needs the plugin's folds (|tern-folding|); without them, a one-line
    head is drawn in place like a block's opener, and a longer one stays
    as it is. |:TernRender| off opens it. Highlights: |hl-TernVirtVerbatim|
    for ⟨head⟩, |hl-TernVirtName| for the rest.

HTML code blocks (|tern-option-render.conceal|)
    A <style> or <script> block in the note is drawn like a block with a
    verbatim body: tinted, its name in place of a start tag alone on its
    line, and an end tag alone on its line hidden. Its code stays as
    written.

TeX as Unicode                                                      *tern-tex*
    lua/tern/tex.lua reads a small subset of KaTeX: Greek letters and
    symbols, function names, the superscripts and subscripts that Unicode
    has (x^2, x_i, x^{-1}), \mathbb and the other alphabets, \frac and
    \sqrt written on one line, accents on one letter, \text, and
    \left … \right. Spacing follows TeX's atom classes, not the source.
    Examples:
        \alpha + \beta        α + β
        x^2 + y_i             x² + yᵢ
        \mathbb{R}^n          ℝⁿ
        \frac{a+b}{c}         (a + b)/c
        \sum_{i=1}^n i        ∑ᵢ₌₁ⁿ i
        \forall x\in A        ∀x ∈ A
    Aligned environments are read line by line when each row is on a line
    of its own, every row but the last ending in `\\`, between `\begin`
    and `\end` lines: align, align*, aligned, split, alignat, alignat*,
    alignedat (columns aligned right and left, around each `&`), gather,
    gather*, gathered (rows centred), and equation, equation*, alone or
    around one of the others. `\nonumber` and `\notag` show nothing.
    Cases and matrices are read the same way, their delimiters drawn as
    tall as their rows: cases, dcases, rcases, drcases (columns aligned
    left), matrix, smallmatrix, pmatrix, bmatrix, Bmatrix, vmatrix,
    Vmatrix (columns centred; the starred forms take [l], [c] or [r]), and
    array, its columns aligned as its l, c and r say. Math may come before
    `\begin` on its line and after `\end` on its line, and is drawn beside
    the middle row; `\left` and `\right` there are the delimiters of an
    array, matrix or aligned:
        $$
        f(x) = \begin{cases}
          1 & x > 0 \\                    ⎧ 1   x > 0
          0 & x = 0 \\             f(x) = ⎨ 0   x = 0
          -1 & x < 0                      ⎩ −1  x < 0
        \end{cases}
        $$
        $$
        A = \begin{pmatrix}
        a & b \\                   A = ⎛a  b⎞
        c & d                          ⎝c  d⎠
        \end{pmatrix}
        $$
    A brace over an even number of rows starts on the `\begin` line, so
    that its middle is on a row.
    The TeX is read after the note's macros, which every formula shares,
    as on the page: the string values of `window.TERN.katex.macros` in the
    head, then the definitions of each `:::macros` block, in the note's
    order, wherever the formula is. `\def`, `\gdef`, `\edef`, `\xdef`,
    `\let`, and `\newcommand`, `\renewcommand` and `\providecommand` with
    their `[n]` arguments are read:
        :::macros
        \gdef\R{\mathbb{R}}
        \gdef\norm#1{\lVert #1 \rVert}
        :::
        $\norm{x} \in \R^n$      ‖x‖ ∈ ℝⁿ
    A definition with delimited parameters or a default for an optional
    argument is not read, and a formula that uses it keeps its source, as
    does one whose expansion does not end.
    When any part of a formula has no faithful Unicode form, such as a
    matrix on one line, `\tag` or a superscript q, the formula gets no Unicode
    text, because a partial conversion would misread it, and its source
    stays. Beside the source, a formula whose Unicode form reads the same
    as the source gets none either; in its place, `$x$` reads `x`.

When it is drawn
    On each outline: when the note opens, and after each analysis, 150 ms
    after you stop typing. In between, the text moves with your edits. An
    outline older than the buffer is not drawn, and text whose line no
    longer holds what the outline says is left out.

The virtual text needs the language server. Turn it off in one buffer with
`:TernRender off` (|:TernRender|), for every note with
|tern-option-render.enabled|, or one kind at a time with its flag.

8. PREVIEW                                                      *tern-preview*

|:TernPreview| serves the note's project over HTTP from inside Neovim, with
Neovim's own event loop. It needs no Node and no other program. It refreshes
the browser as you change a note, before you write it, and each time you
write a file.

How it works                                                *tern-preview-how*

Root and URL. The server's root is the note's project: the nearest directory
above the file that holds tern.js or .git, else the file's own directory. A
file's URL is its path under the root, so the note's relative URLs (tern.js,
add-ons, images, other notes) resolve as they do on disk: >
    tern: preview at http://127.0.0.1:41723/notes/maps.html
<
One server per Neovim. |:TernPreview| on another file under the same root
reuses the server and gives that file's URL. On a file outside the root, the
server moves to the new root. With |tern-option-preview.port| 0 it keeps its
port when it can, so the old root's pages reload into "404 Not Found"
instead of retrying forever.

What it serves. Files under the root, to GET and HEAD requests. A directory
serves its index.html; a directory URL without its final slash is
redirected. Byte ranges are supported, so audio and video can seek. The
content type comes from the file's extension, and every response has
"Cache-Control: no-store".

Notes. A note (an .html or .htm file that is a note, up to 16 MiB) is served
with two additions on its tern.js line:
• `data-diagnostics` on the tern.js tag, so that tern.js shows its
  diagnostics panel;
• `<script src="/__tern/live.js" …>` just before that tag: the live reload
  script. It gets the tag's nonce, when the tag has one.
Both go on the same line, so every other line stays where it is, and the
line numbers in the diagnostics panel stay right. The file on disk is not
changed.

Live reload. When you write a file under the root in this Neovim
(|BufWritePost|), the server tells every open page with a Server-Sent Event
on /__tern/events. Writes within 30 ms of each other, as from |:wall|, make
one event. Each page then acts on it:
• The page of the note you wrote refreshes in place and keeps its scroll
  position. It fetches the file and renders the new note with tern.js,
  without reloading the page.
• That page reloads instead, still keeping its scroll position, when the
  lines up to the tern.js line changed, or when the tern.js tag is not
  closed on its own line (`</script>` on the same line).
• A write of a file that is not a note (CSS, an add-on, an image) reloads
  the page.
• A write of another note leaves the page alone.
A page whose connection drops reconnects, waiting longer each time, up to
8 seconds, and reloads once the server is back.

                                                        *tern-preview-unsaved*
Unsaved notes. With |tern-option-preview.update| 'change', a note whose
buffer is modified is served from the buffer instead of its file: the
page, and the raw note it fetches to refresh. The text is what |:write|
would put on disk, with the buffer's 'fileformat', 'eol' and 'bomb', taken
150 ms after the last change (|TextChanged|, |TextChangedI|). Its pages
then get the same event as for a write, and refresh in place the same way.
Once the buffer is written, is back to its file (|:undo| to the written
text, |:edit!|) or is unloaded, the file is served again. A note that was
modified before |:TernPreview| is served from its buffer from the first
request. Only notes are served this way: CSS, add-ons and images refresh
when you write them. The file on disk is never changed.

Security                                               *tern-preview-security*

The server is meant for your own browser on this machine:
• It listens on |tern-option-preview.host|, 127.0.0.1 by default, so other
  machines cannot connect.
• It answers GET and HEAD only.
• The Host header must be HOST:PORT, localhost:PORT or 127.0.0.1:PORT. This
  defeats DNS rebinding, in which a web page reaches a local server through
  a name that resolves to 127.0.0.1.
• A request that another site's page makes (Sec-Fetch-Site cross-site or
  same-site) is refused unless it is a navigation. Every response has
  "X-Content-Type-Options: nosniff" and
  "Cross-Origin-Resource-Policy: same-origin". Other pages can link to the
  preview, but cannot read or embed its files.
• A path must resolve inside the root, with symbolic links followed, so
  neither `..` nor a link leaves it.
• Nothing whose name starts with a dot is served, at any depth (.git,
  .env). Only regular files are served, not FIFOs or devices, and there
  are no directory listings.
• The request line and headers are capped at 8 KiB and 5 seconds, and open
  connections at 64.

Limits                                                   *tern-preview-limits*

• Unsaved changes show for notes only, and with
  |tern-option-preview.update| 'write' not at all: write the buffer.
• Each refresh renders the whole note again in the browser, KaTeX
  included, so a large note's page lags behind fast typing. Changes made
  while it renders are taken in one more render.
• Only writes in this Neovim refresh the page. When another program changes
  a file, such as a build step or git, reload the page yourself.
• There is no authentication and no TLS. With |tern-option-preview.host|
  set to an address that other machines reach, anyone who reaches it can
  read every file under the root but the hidden ones. The Host check then
  accepts only that address, localhost and 127.0.0.1.
• There is one preview per Neovim, with one root at a time.
• A note larger than 16 MiB is served unchanged, without live reload.
• URLs under /__tern/ belong to the server, so a folder named __tern at the
  root cannot be served.
• A buffer whose file is a link to a file outside the root cannot be
  previewed.

9. HIGHLIGHTING                                 *tern-highlight* *tern-syntax*

syntax/tern.vim highlights notes without the language server. It is a
lexical approximation: each construct is recognised from its own text, so it
is fast and never breaks on a long note. The exact structure (the depth of
raw HTML, the pairing of emphasis, the lines a list item owns) comes from
the language server. Line constructs are also recognised after `>` quote
markers. The head, every line up to and including the tern.js line, is
highlighted as HTML.

Up to 20,000 lines, the syntax is parsed from the start of the file, which is
exact; the first full parse costs about 50 ms per 1,000 lines. In a longer
note, parsing starts 500 lines above the window, so a fence or raw block
longer than that may be misread until it scrolls into view.

10. HEALTH                                                       *tern-health*

`:checkhealth tern` checks the buffer you ran it from, else the current
directory. Its sections:
• Neovim: the version, which must be 0.11 or later.
• Node: the `node` on PATH, which must be version 22 or later.
• Command line: $TERN_CLI when it is set. Then the language server command
  for the buffer and the source that found it (|tern-cli-lookup|), or why
  none was found. It warns when |:TernCheck| and |:TernBuild| cannot run.
• Language server: each running tern client, with its root and its number
  of buffers, and whether the buffer is attached and has an outline yet.
  With |tern-option-lsp| false, it says the server is off.
• This buffer: whether it is a note, with the line and the tag that make it
  one, and its filetype.
• Options: the options in effect.

11. WITHOUT NODE                                           *tern-without-node*

Without Node 22 or later, or without the Tern CLI, the language server
cannot start. When the first note opens, the plugin says why, once a
session, and goes on. For example: >
    tern.nvim: the language server cannot start: node is not on PATH; Tern
    needs Node 22 or later. Notes fold by headings only, without
    diagnostics or completion (:checkhealth tern).
<
These still work:
• detection and the filetype `tern`;
• highlighting (|tern-highlight|);
• folding by headings (|tern-lexical-folds|);
• |:TernInit|;
• |:TernPreview| and its live reload, because the server runs in Neovim and
  the browser runs tern.js;
• `:checkhealth tern`.

These do not: diagnostics, completion, definition, references, rename,
hover, symbols, the server's folds, |:TernMove|, and the virtual text, which
is drawn from the server's outline. |:TernCheck| and |:TernBuild| say why
they cannot run.

With |tern-option-lsp| false, notes behave the same, without the notice, and
|:TernCheck| and |:TernBuild| still work when Node and the CLI are there.

12. THE API FOR USERS                                               *tern-api*

These modules are for your config and for other plugins. Each loads on first
use. {buf} is a buffer number, where 0 means the current buffer.

require('tern') ~

setup({opts})
    Sets the options. See |tern.setup()|.

attach({buf})                                                  *tern.attach()*
    Starts the language server for {buf} (with |tern-option-lsp| false,
    folds it by headings instead) and the virtual text. ftplugin/tern.lua
    calls it for each buffer whose filetype becomes `tern`.

require('tern.lsp') ~

start({buf})                                                *tern.lsp.start()*
    Starts the server for {buf}'s root, or attaches {buf} to the one that
    runs, and sets its folds. Returns the client id. When no server can
    start, returns nil, folds {buf} by headings and, once a session, says
    why.

client({buf})                                              *tern.lsp.client()*
    The `tern` client (|vim.lsp.Client|) attached to {buf}, or nil.

outline({buf})                                            *tern.lsp.outline()*
    The last `tern/outline` params for {buf}, or nil before the first one.
    See |tern-outline|.

lexical({buf})                                            *tern.lsp.lexical()*
    Folds {buf} by headings, without a server (|tern-lexical-folds|).

foldexpr({lnum})                                         *tern.lsp.foldexpr()*
    The 'foldexpr' that lexical() sets: the fold level of line {lnum} in
    the current buffer.

restart_window                                       *tern.lsp.restart_window*
    In milliseconds, 60000 by default. A server that crashes again within
    this time of its restart is not restarted.

require('tern.render') ~

attach({buf})                                           *tern.render.attach()*
    Draws the virtual text in {buf} now, and again on each |TernOutline|.

command({args})                                        *tern.render.command()*
    What |:TernRender| runs on the current buffer. {args} is 'on', 'off' or
    'toggle', or the table a user command receives.

draw({buf}, {outline})                                    *tern.render.draw()*
    Draws {outline}, a table shaped like the result of |tern.lsp.outline()|,
    over {buf}, replacing what was drawn. It follows the
    |tern-option-render| flags. The |TernOutline| event calls it; you can
    call it to draw an outline of your own.

enabled({buf})                                         *tern.render.enabled()*
    Whether {buf} shows the virtual text, for a statusline.

ns                                                            *tern.render.ns*
    The namespace of the virtual text's extmarks.

require('tern.preview') ~

start()                                                 *tern.preview.start()*
    What |:TernPreview| runs for the current buffer. Returns the page's URL,
    or nil when the file cannot be served; it then says why.

stop({quiet})                                            *tern.preview.stop()*
    What |:TernPreviewStop| runs. With {quiet} true, it prints nothing.

info()                                                   *tern.preview.info()*
    The running server as { root, url, host, port, clients }, or nil. `url`
    is the base http://HOST:PORT, and `clients` the number of pages that
    listen for reloads.

require('tern.detect') ~

line({s})                                                 *tern.detect.line()*
    Whether the line {s} makes a file a note (|tern-detection|). Returns
    { col, tag }, where col is the 1-based byte column of the tag and tag is
    the `<script …>` tag, or nil.

buffer({buf})                                           *tern.detect.buffer()*
    The first line of {buf} that makes it a note, as { lnum, col, tag }, or
    nil. Only the first max_lines lines are read.

max_lines                                              *tern.detect.max_lines*
    How many lines detection reads: 1000.

For example: >lua
    local d = require('tern.detect').buffer(0)
    if d then
      print('tern.js is loaded on line ' .. d.lnum)
    end

13. TROUBLESHOOTING                                     *tern-troubleshooting*

Start with `:checkhealth tern` in the note (|tern-health|).

The language server does not start ~
The notice says why, and so do the Node and Command line sections of the
health check. The usual causes:
• `node` is missing or older than 22. Install Node 22 or later. Each node
  binary is checked once a session, so restart Neovim after an upgrade.
• No tern-cli.js was found. Run `npm link` in a Tern checkout, set
  $TERN_CLI, or set |tern-option-cmd|.
• The `tern` on PATH is another program. It is skipped, because an npm
  package of that name is not Tern; use $TERN_CLI or `cmd`.
• "… exited before it started": the command runs, but is not a language
  server, for example a wrong path in `cmd`. Run it in a terminal to see
  why.
The notice comes once a session. After you fix the cause, |:edit| the note
to start the server.

The file does not get the filetype tern ~
• The name must end in .html or .htm.
• The tern.js line must be within the first 1000 lines and follow the rule
  in |tern-detection|.
• After you add the line by hand, run `:filetype detect` or |:edit|.
  |:TernInit| sets the filetype itself.

No virtual text ~
• It needs the language server: see above.
• With |tern-option-render.enabled| false, run `:TernRender on`.
• It is drawn when an outline arrives: when the note opens, and 150 ms
  after you stop typing.
• Only labelled blocks, references that resolve, equation numbers, and
  formulas with a faithful Unicode form get text.

The folds are not the ones I set ~
With |tern-option-fold| true, the plugin sets 'foldmethod', 'foldexpr',
'foldlevel' and 'foldtext' in each window that shows a note. Set
`fold = false` to keep your own.

:TernCheck or :TernBuild cannot run ~
They need the CLI, found like the server's (|tern-cli-lookup|). When `cmd`
is a function, or a list without `lsp`, they use the other sources, and the
health check warns when none finds the CLI.

The preview does not change ~
• With |tern-option-preview.update| 'write', or for a file that is not a
  note (CSS, an add-on), write the buffer: the preview serves the file on
  disk.
• Changes made by other programs do not refresh the page; reload it.
• The page reloads instead of refreshing in place when the tern.js tag is
  not closed on its own line, or when the head changed.
• "the port is in use": set |tern-option-preview.port| to another port, or
  to 0 for any free port.
